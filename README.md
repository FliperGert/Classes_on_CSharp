# Задание 1

## Задача 1 Имена

### Текст задачи

Создайте сущность Имя, которая описывается тремя параметрами: Фамилия, Личное имя,
Отчество. Имя может быть приведено к строковому виду, включающему традиционное
представление всех трех параметров: Фамилия Имя Отчество (например “Иванов Иван
Иванович”). Необходимо предусмотреть возможность того, что какой-либо из параметров может
быть не задан, и в этом случае он не учитывается при приведении к текстовому виду.
Необходимо создать следующие имена:
• Клеопатра
• Пушкин Александр Сергеевич
• Маяковский Владимир
Обратите внимание, что при выводе на экран, не заданные параметры никак не участвуют в
образовании строки.

Необходимо создать следующие имена: Клеопатра; Пушкин Александр Сергеевич; Маяковский Владимир.

### Алгоритм решения

Класс Name описывает имя человека тремя частями: фамилией, личным именем и отчеством. Каждая часть хранится в закрытом поле (_surname, _firstname, _middlename), а доступ к ним сделан через обычные свойства Surname, Firstname и Middlename (без автосвойств). Фамилия и отчество могут быть не заданы, тогда в них хранится null.

В свойстве Firstname есть проверка: если передали пустую строку или одни пробелы, на экран выводится сообщение «Личное имя должно быть задано», а в поле записывается запасное значение Ivan(null), чтобы программа не падала. Если имя нормальное, оно просто записывается.

Метод ToString() собирает строку по шагам:

1. Берём личное имя и записываем его в строку result.
2. Если фамилия задана (не null и не состоит из одних пробелов), приписываем её в начало: «Фамилия Имя».
3. Если отчество задано, дописываем его в конец: «Фамилия Имя Отчество».
4. Возвращаем result.

Из-за этих проверок незаданные части никак не участвуют в строке: «Клеопатра» выводится одним словом, «Маяковский Владимир» двумя, «Пушкин Александр Сергеевич» тремя. В программе создаются три объекта Name и выводятся на экран циклом for.

# Задание 2

## Задача 1 Человек с именем

### Текст задачи

Человек с именем.
Объедините сущности Человек из задачи 1.2 и Имя из задачи 1.3 таким образом, чтобы имя
человека задавалось с использованием сущности 1.3, а не строки.
Необходимо объединить ранее созданные объекты имен и людей, с получением:
• Человека с Именем Клеопатра и ростом 152
• Человека с Именем Пушкин Александр Сергеевичи ростом 167
• Человека с Именем Маяковский Владимир и ростом 189

### Алгоритм решения

Класс Human описывает человека. Имя хранится в поле _name не строкой, а объектом типа Name, поэтому оно может состоять из фамилии, имени и отчества. Рост хранится в поле _height и доступен через свойство Height.

В сеттерах свойств есть проверки:

1. Name: если передали null, выводится сообщение «Имя не может быть null», а в поле записывается запасное имя Inav(null). Иначе имя записывается и вызывается FillFromFather() (он нужен для задачи с отцом).
2. Height: если значение больше нуля, рост записывается. Иначе выводится сообщение «Отрицательный рост быть не может», а рост становится равным 1.

Человек создаётся конструктором Human(Name name, int height). Он вызывает главный конструктор, который присваивает значения не напрямую в поля, а через свойства, поэтому проверки срабатывают уже при создании объекта. Метод ToString() возвращает строку «имя, рост: число», где имя получается вызовом ToString() у объекта Name.

В программе создаются три объекта Name (Клеопатра, Пушкин Александр Сергеевич, Маяковский Владимир). Для каждого создаётся Human с ростом 152, 167 и 189, после чего все три выводятся на экран.

## Задача 2 Человек с родителем

### Текст задачи

Измените сущность Человек из задачи 2.2 добавив ему возможность задавать третий параметр:
Отец, где Отец — это тоже Человек. При приведении человека к строковой форме необходимо
проверить параметры имени, и в зависимости от ситуации выполнить одно из следующих
действий:
• Если у данного человека нет фамилии, и есть отец, у которого фамилия задана, то
фамилию необходимо сделать такой же как у отца.
• Если у данного человека нет отчества, а у отца есть имя, то необходимо задать отчество
как имя отца с добавлением суффикса “ович”.
Затем необходимо выполнить следующие задачи:
1. Создать людей: Чудова Ивана, Чудова Петра, Бориса
2. Сделать Ивана отцом Петра, а Петра отцом Бориса
3. Вывести на экран строковое представление всех троих людей.
При желании можно попытаться реализовать систему в более полном виде: предусмотреть
разные виды суффиксов отчества в зависимости от окончания имени, а также предусмотреть
возможность задавать пол человека и менять суффикс отчества в зависимости от пола.

### Алгоритм решения

В класс Human добавляем поле _father типа Human и свойство Father, то есть отец тоже является человеком. Вся логика заполнения собрана в приватном методе FillFromFather(). Он работает так:

1. Если отца нет (или имя не задано), метод сразу заканчивается.
2. Если у человека не задана фамилия, а у отца она задана, фамилия копируется от отца.
3. Если у человека не задано отчество, а у отца задано личное имя, отчество строится из имени отца методом MakeMiddlename().

Метод MakeMiddlename() выбирает суффикс по последней букве имени отца:

- «й» или «ь»: убираем последнюю букву и добавляем «евич» (Сергей → Сергеевич);
- «я»: убираем её и добавляем «ьич» (Илья → Ильич);
- «а»: убираем её и добавляем «ич» (Никита → Никитич);
- любая другая буква: просто добавляем «ович» (Иван → Иванович).

FillFromFather() вызывается в трёх местах: в сеттере Name, в сеттере Father и в начале ToString(). Поэтому результат правильный и если отец задан при создании, и если его назначили позже, уже после создания человека.

В программе создаём Ивана и Петра с фамилией Чудов и Бориса без фамилии. Затем выполняем petr.Father = ivan и boris.Father = petr и выводим всех троих. У Петра появляется отчество Иванович, а Борис получает фамилию Чудов и отчество Пётрович (к имени «Пётр» просто добавляется «ович»).

Создайте сущность Город, которая будет представлять собой точку на карте со следующими
характеристиками:
• Название города
• Набор путей к следующим городам, где путь представляет собой сочетание Города и
стоимости поездки в него.
Кроме того, Город может возвращать текстовое представление, в виде названия города и списка
связанных с ним городов (в виде пары: “название:стоимость”).

### Алгоритм решения

Для решения нужны два класса. Класс Route описывает один путь: город, куда ведёт путь (Destination), и стоимость поездки (Cost). Его метод ToString() возвращает пару в виде «название:стоимость».

Класс City хранит название города _name и список путей _routes типа List<Route>. Список создаётся в конструкторе, поэтому у любого города он изначально пустой. У класса есть три метода:

1. AddRoute(destination, cost) создаёт новый Route и добавляет его в список. Это путь в одну сторону.
2. Connect(a, b, cost) (статический) вызывает AddRoute у обоих городов, поэтому между ними появляется путь в обе стороны с одинаковой ценой.
3. ToString() в цикле проходит по всем путям, склеивает их через запятую и возвращает строку вида «A: [B:5, F:1, D:6]».

Схему с рисунка 2 собираем в программе так:

1. Создаём шесть городов: A, B, C, D, E, F.
2. Пути в обе стороны создаём через Connect: A–B (5), F–E (2), B–C (3), C–D (4), A–D (6).
3. Пути в одну сторону создаём через AddRoute: A→F (1), F→B (1), D→E (2).
4. Выводим все города на экран.
5. Пользователь вводит название города (ввод проверяется методом InputString), и в цикле for программа ищет город, название которого совпадает с введённым. Регистр важен: нужно вводить A, а не a. Если такого города нет, выводится сообщение об этом.

## Задача 1 Создаем Имена

### Текст задачи

Создаем Имена.
Измените сущность Имя из задачи 1.3. Новые требования включают:
• Имя можно создать указав только Личное имя
• Имя можно создать указав Личное имя и Фамилию.
• Имя можно создать указав все три параметра: Личное имя, Фамилию, Отчество.
Необходимо создать следующие имена:
1. Клеопатра
2. Александр Сергеевич Пушкин
3. Владимир Маяковский
4. Христофор Бонифатьевич (здесь Христофор это имя, а Бонифатьевич - фамилия)

### Алгоритм решения

В классе Name теперь три конструктора, и каждый соответствует одному способу создания имени:

1. Name(firstname) создаёт имя только с личным именем.
2. Name(firstname, surname) создаёт имя с личным именем и фамилией.
3. Name(firstname, surname, middlename) создаёт имя со всеми тремя параметрами.

Порядок параметров всегда один: сначала личное имя, потом фамилия, потом отчество. Присваивания (через свойства) выполняются только в третьем, самом полном конструкторе. Первые два вызывают его через this(...), а вместо отсутствующих данных передают null. Так код не дублируется.

Имена из задания создаются так:

- «Клеопатра»: new Name("Клеопатра");
- «Александр Сергеевич Пушкин»: new Name("Александр", "Пушкин", "Сергеевич");
- «Владимир Маяковский»: new Name("Владимир", "Маяковский");
- «Христофор Бонифатьевич»: new Name("Христофор", "Бонифатьевич"), где второй параметр является фамилией.

Метод ToString() всегда ставит фамилию первой (порядок «Фамилия Имя Отчество»), поэтому последнее имя выводится как «Бонифатьевич Христофор». Все четыре имени выводятся нумерованным списком.

## Задача 2 Создаем Человека

### Текст задачи

Создаем Человека. Измените сущность Человек из задачи 2.3. Новые требования включают:
• Человека можно создать с указанием имени в виде строки и роста в виде целого числа.
При таком способе задания имени должно считаться, что Человеку задано только личное
имя.
• Человека можно создать с указанием имени в виде строки, роста в виде целого числа и
отца в виде Человека. В этом случае необходимо проставить отчество в соответствии с
именем отца и присвоить текущему человеку фамилию отца.
• Человека можно создать с указанием имени в виде объекта типа Имя (из задачи 4.5) и
роста в виде целого числа.
• Человека можно создать с указанием имени в виде объекта типа Имя (из задачи 4.5),
роста в виде целого числаи отца в виде Человека. В этом случае необходимо проверить
что в Имени задано отчество и фамилия, и если они не заданы, то необходимо их задать
(отчество в соответствии с именем отца и фамилию отца).
• Реализуйте описанные способы создания Человека таким образом, чтобы операции
присвоения использовались только в одном из конструкторов.
• Необходимо модифицировать способ приведения Человека к строке, теперь текстовая
форма должна быть представлена строкой: “Имя, рост”
Создайте и выведите на экран следующие объекты:
1. Человека с именем Лев (в виде строки) и ростом 170
2. Человека с именем Пушкин Сергей (как Имя), ростом 168 и отцом Львом (предыдущий Человек)
3. Человека с именем Александр (в виде строки), ростом 167 и отцом Сергеем (предыдущий
Человек)

### Алгоритм решения

В классе Human теперь четыре конструктора, по одному на каждый способ создания человека:

1. Human(string name, int height): имя строкой и рост. Вызывает четвёртый конструктор, превращая строку в new Name(name) и передавая вместо отца null. Человеку задано только личное имя.
2. Human(string name, int height, Human father): имя строкой, рост и отец. Вызывает четвёртый конструктор, превращая строку в new Name(name).
3. Human(Name name, int height): имя объектом Name и рост. Вызывает четвёртый конструктор с null вместо отца.
4. Human(Name name, int height, Human father): имя объектом, рост и отец. Это единственный конструктор, в котором есть присваивания: Name = name, Height = height, Father = father.

Первые три конструктора только перенаправляют вызов через this(...), поэтому присваивания используются только в одном конструкторе, как и требуется в задании.

Недостающие данные подставляются при присвоении отца: сеттер Father вызывает метод FillFromFather() (описан в предыдущей задаче). Он берёт фамилию отца и строит отчество из его имени, но только если у человека они не заданы. Метод ToString() возвращает строку «имя, рост: число».

В программе создаются три человека:

1. Лев: new Human("Лев", 170), без фамилии и отчества.
2. Сергей: new Human(new Name("Сергей", "Пушкин"), 168, lev). Фамилия уже есть, а отчество «Левович» строится от имени отца.
3. Александр: new Human("Александр", 167, sergey). Он получает фамилию «Пушкин» и отчество «Сергеевич».

## Задача 1 Кот мяукает

### Текст задачи

Кот мяукает.
Создайте сущность Кот, которая описывается следующим образом:
• Имеет Имя (строка)
• Для создания необходимо указать имя кота.
• Может быть приведен к текстовой форме вида: “кот: Имя”
• Может помяукать, что приводит к выводу на экран следующего текста: “Имя: мяу!”,
вызвать мяуканье можно без параметров.
• Может помяукать Nраз, что приводит к выводу на экран следующего текста: “Имя: мяумяу-…-мяу!”, где количество “мяу”равно N.
Создайте кота по имени “Барсик”, и затем пусть он помяукает сначала один раз, а затем три раза.

### Алгоритм решения

Класс Cat описывает кота. Имя хранится в закрытом поле _name, а в сеттере свойства Name стоит проверка: если имя пустое, выводится сообщение «У кота должно быть имя», а коту даётся запасное имя Барсик(null). Конструктор у класса один, Cat(string name), и он присваивает имя через свойство, поэтому проверка срабатывает при создании кота.

У кота два метода мяуканья с одним названием Meow:

1. Meow() без параметров выводит на экран «Имя: мяу!».
2. Meow(int n) создаёт пустую строку result и в цикле for повторяет n раз следующие действия: если это не первое слово, добавляет к строке дефис, затем добавляет слово «мяу». После цикла выводит «Имя: » + result + «!». Например, при n = 3 получится «Барсик: мяу-мяу-мяу!».

Метод ToString() возвращает строку «кот: Имя».

В программе создаётся кот «Барсик», выводится его текстовая форма, затем вызываются Meow() и Meow(3). Дополнительно пользователь может создать своего кота: имя вводится через InputString (оно не должно быть пустым и содержать цифры), а число «мяу» через InputInt в диапазоне от 1 до 20.
